# Sesame 界面设计

Sesame（芝麻开门）是一个常驻菜单栏的 macOS 小工具。按热键，屏幕中上方浮出一个面板，说一句或打一句，它从你和 Claude Code / Codex 的对话里把 AI 交付过的产物找出来打开，或者执行一个系统动作。

- 原型：`prototype.html`（单文件，零外部依赖，直接用浏览器打开）
- 预览图：`png/`（2x，2560×1600，每张不超过 1MB；另附 16:9 的推特裁切（宣传图一律用中性石墨背景，按 `?promo=1` 渲染，不带桌面壁纸；App 状态图仍用桌面壁纸）：设置里接管 ⌘Space `16a-takeover-spotlight(-dark).png` / `16c-takeover-done(-dark).png`；首次启动开场 `11-first-run-16x9.png` / `11-first-run-dark-16x9.png`，成功态 `03-success-16x9.png` / `03-success-dark-16x9.png`）
- 标志定稿：`logo/final/`（`app-icon.svg` / `menubar.svg` / `wordmark.svg` / `AppIcon.appiconset/`）；比稿过程：`png/logo-board.png`、`png/logo-sesame-board.png`、`png/logo-sesame-v3-board.png`
- 重新截图：`node design/tools/shoot.mjs 1 2 3 3d …`（需要本机 Chrome 开着 9222 调试端口）

## 第一原则：面板只展示用户要的结果

面板里只出现用户要的结果：打开了什么、查到了什么、要他确认什么、下一步需要他给什么。**系统内部的实现细节一律不上面板**：用了哪个模型、花了多少 token、多少钱、是缓存命中还是走模型、经过哪条路由。换成小灰字、悬浮提示、角标都不行。

这些信息只对自带 key、在乎用量的用户有意义，放在「设置 → 用量」页，菜单栏下拉里也不出现。

由此带来的两个直接结果：

- 缓存命中和走模型在界面上完全一样，原型里只保留一个「成功」状态（按键 3；旧链接 `#4` 自动落到 3）。
- 结果区是唯一的主角，没有和它争注意力的二级元素。

## 成功态右侧：留空

二选一的结论是**留空**，不放「↩ 再次打开 / ⌘C 复制链接」。理由：

1. 成功态出现的那一刻，产物已经在前台打开了。用户的视线在新打开的窗口上，面板随后就会收起，此时放在右侧的按钮几乎没有人会用到。
2. 「再次打开」重复了刚刚发生的动作；「复制链接」只对网页和本机服务有意义，对文件、系统动作不成立，放上去就要为不同类型准备不同的按钮，规则变复杂。
3. 需要复制链接时，再说一句「复制刚才的链接」就行，这本来就是这个产品的交互方式。
4. 右侧空出来以后，这一行只剩图标、「已打开 交易大盘」和一行出处，第一眼就能读完，推特截图的重点也只有这一句话。

候选列表的选中行仍然显示 ↩，因为那里用户确实还没做选择，回车是他下一步要按的键。

## 第二批功能：交互设计三问（2026-10-02）

产品负责人勾选的四个功能：首次启动开场、边打字边出结果、开机自启、系统自带语音输入。先回答三问再画；说不出存在理由的元素没有画。

### 1. 首次启动开场（按键 4）

**场景**：装完第一次打开，Sesame 刚读完本机的 Claude Code / Codex 记录。用户还不知道它能干什么，也不知道该说什么。这一屏也要能直接截图当推特主图。

**每个元素为什么在**

| 元素 | 理由 |
|---|---|
| 大字「动动嘴，就调出来。」 | 一句话说清这个产品给你什么：不用翻会话，说一句就回来。文案在本地化 key `intro.headline`，代码和原型里都不写死 |
| 「2,708 个 AI 产物，一句话的事。」 | 用户第一次意识到「原来做过这么多、全都找得回来」，这就是安装的理由；数字加粗加大，从 0 滚到终值（1.2s，只滚一次）。文案在 `intro.count`，`%@` 是数字 |
| 「来自你和 Claude Code、Codex 的全部对话」 | 说明数字从哪来，不说就像吹牛 |
| 分组计数（看板 / 报告 / PPT / 网站 / PR / 文件） | 证明数字是真的、并且是产物而不是聊天记录；值为 0 的组不显示，格子按剩下的组重新排（3 列；少于 3 组时排成一行），和分享卡的规则一致（`IntroCounts.visible` / `IntroCounts.columns`） |
| 「试试：打开上周那个交易大盘」+ ↩ | 把下一步直接递到手上；示例用用户自己真实产物的标题生成，回车立刻打开，第一次体验就是一次成功 |
| 输入条占位「打一句话，或按住 <当前生效的键> 说」 | 同时教会两种输入方式，不另加教程页；键名跟着实际生效的键走（默认 ⌥⇧Space，在设置里接管后是 ⌘Space），不写死 |
| 「分享」小按钮（来源那一行的右端） | 让愿意晒数字的人一键拿到图，见下面「6. 分享我的数字」；次级按钮，样式同「换一个」，永远不是默认按钮 |

删掉的：欢迎语、功能介绍列表、「下一步」按钮、隐私声明长文（隐私说明放在麦克风权限页那一句）。

**层级**：一级是那句大字和带数字的一行；二级是分组计数；三级是「试试」那一行（视觉上弱，但它是唯一能按回车的地方，所以默认选中）；「分享」按钮和来源说明同级，最弱。

**私人内容**：开场里只出现计数和一条示例。对外图里的示例一律用通用名称（交易大盘、年度大事记、大客户名单这类），不出现任何真实用户自己的产物名。示例标题从用户产物里挑「通用名词」类的（看板、周报这类），挑不到合适的示例就不显示这一行。截图里的数字和示例都是演示数据。

### 2. 边打字边出结果（按键 t 播放，帧 #t0 到 #t3）

**场景**：用户已经知道自己要什么，只想打两个字直接跳过去，像 Spotlight。

**规则**

- **结果长在输入框正下方**，面板顶边固定不动，只向下长。最多显示 6 行，多出的在列表内滚动。
- **0 条**（还没打字，帧 t0）：只有输入条，没有分隔线、没有空列表。
- **0 到 N 条**（帧 t1，打了「大」）：分隔线出现，面板高度 260ms 展开，行依次淡入（每行错开 25ms）。
- **N 到 M 条**（继续打字）：高度直接过渡到新值，行就地替换，不再做入场动画，避免每敲一个字整列表闪一下。
- **N 到 1 条**（帧 t2，打到「交易大」）：同上，高度收缩。
- **匹配到 0 条**（帧 t3，打到「交易大盘 v2」）：保留一行「让 Sesame 去找「…」」，回车后走原来的完整流程（意图预览到结果）。这一行存在的理由：本地即时匹配找不到时，回车仍然要有一个明确的去处。
- **选中态**：用户没按过方向键时，选中永远是第一条；按过方向键后，选中跟着「那一条结果」走，只要它还在列表里，位置变了也跟着；它消失了才回到第一条。
- **粘贴进来的一整句**（含空格或动词、长度超过 6 个字，比如「打开上周让 Claude 做的那个交易大盘」）：不停在即时列表，直接自动执行，进入意图预览，和说出来的一样。
- 即时列表里不显示意图行，意图行只在执行时出现。
- **已装的 App 也在这张列表里**（⌘Space 交给 Sesame 后，打 App 名第一行就得是那个 App，和聚焦搜索一样）：真实图标 + App 名 + 类型徽标「应用」，回车直接打开。排序：App 前缀命中 > AI 产物名称命中 > App 子串命中 > 其他。完整规则和理由见 [docs/live-ranking.md](../docs/live-ranking.md)。
- 只被提到过、不是 AI 做的外部网页（别人贴的 GitHub 仓库、博客）不进这张列表，除非用户自己打了「网页 / 链接 / 文章」；没对上 AI 产物时也不拿它们兜底。

**层级**：一级是选中行；二级是其他行；类型徽标和地址是三级。

### 3. 开机自启（按键 s）

**场景**：用户在菜单栏图标里点「设置…」，想确认或关掉开机启动。

**元素**：只有一行「登录时打开 Sesame」+ 说明「开机后在菜单栏待命，按 <当前生效的键> 就能用」+ 开关，默认打开。说明那一句告诉用户关掉的代价（开机后按热键没反应）。设置窗口其他内容不在本单范围，没有画。

### 4. 系统自带语音输入（按键 v 按住说话，按键 m 麦克风权限）

**快捷键：默认 ⌥⇧Space，⌘Space 在设置里自选（2026-10-03 改定：首次启动不再弹接管卡，见第 5 节）。** 轻按打开面板打字；按住不放超过 300ms 开始听，松开就发送。打开面板和说话始终是同一个键，交互不用另学。界面上所有提到热键的地方（输入条占位、麦克风说明、按住时的键帽、设置说明）都显示**当前实际生效的键**，不写死。

- 为什么提供 ⌘Space：它是 Mac 上最顺手的那个键，想把 Sesame 当第一入口的人可以在设置里换过去。为什么不再用 ⌥Space：原来的 ⌥Space 和 Codex 桌宠（Show Pet / Mini，默认 ⌥Space，且在设置里关不掉）、ChatGPT、Alfred、Raycast 的默认键全部撞车。
- ⌘Space 默认归系统聚焦搜索。**Sesame 不改系统设置**：只读 `com.apple.symbolichotkeys` 第 64 项判断聚焦的 ⌘Space 是否开着，开着就引导用户自己去关（见下面的接管步骤，按键 k）。
- Alfred / Raycast 也可能占着 ⌘Space：读它们自己保存的热键（Alfred 的 `hotkey/prefs.plist`、Raycast 的 `raycastGlobalHotkey`），是 ⌘Space 就不去抢，换一套文案告诉用户去对方设置里改；Sesame 不碰对方的配置。
- 备用键为什么是 ⌥⇧Space：在 ⌥Space 上多按一个 ⇧，手感最接近；同时避开了 ⌥Space（Codex 桌宠 / ChatGPT / Alfred / Raycast 默认）、⌃Space 与 ⌃⌥Space（系统切换输入法）、⌥⌘Space（访达搜索）、⇧⌘Space（1Password 快速访问）、⌃⌘Space（表情与符号）。来源：
  - Codex 桌宠：本机 `/Applications/ChatGPT.app`（bundle `com.openai.codex` 26.928）的 `app.asar` 里 `openAvatarOverlay`（菜单名 Show Mini）的 macOS 默认键是 `Alt+Space`；关不掉见 [openai/codex#49201](https://github.com/openai/codex/issues/49201)、[#45299](https://github.com/openai/codex/issues/45299)；26.831 版一度改成 ⌃Space 见 [#42258](https://github.com/openai/codex/issues/42258)。
  - ChatGPT：[OpenAI 官方推文](https://x.com/OpenAI/status/1820914089612439622)、[Chat Bar 帮助页](https://help.openai.com/en/articles/9295241-how-to-launch-the-chat-bar)，默认 ⌥Space。
  - Alfred / Raycast 默认 ⌥Space：[Alfred 帮助](https://www.alfredapp.com/help/troubleshooting/cmd-space/)、[Raycast 手册](https://manual.raycast.com/settings)。
  - 1Password 快速访问默认 ⇧⌘Space：[1Password 支持页](https://support.1password.com/quick-access/)。Claude 桌面版快速输入默认双击 ⌥：[Claude 帮助](https://support.claude.com/en/articles/12626668-use-quick-entry-with-claude-desktop-on-mac)。
  - 系统：本机 `defaults read com.apple.symbolichotkeys` 的 60（⌃Space）、61（⌃⌥Space）、64（⌘Space 聚焦）、65（⌥⌘Space 访达搜索）。
- 用户在设置里录的键永远优先；点「自动」回到默认：没接管过就是 ⌥⇧Space，接管过就是「⌘Space 空着就用它，不然用 ⌥⇧Space」。
- 「热键被占用」状态（按键 h）保留：当前生效的键注册失败或被已知应用占用时，开场页底部提示一行 + 「换一个」。

### 5. 接管 ⌘Space（设置里自选；按键 k / k2 / k3）

**2026-10-03 改定：首次启动不再弹接管卡。** 装完第一次打开直接用备用键 ⌥⇧Space 进入计数开场；想用 ⌘Space 的人到「设置 → 热键」点「接管 ⌘Space…」，走下面这一整套引导。理由：第一次打开时用户最想看的是「AI 替我做了多少」，先让他决定一个系统快捷键是在打断这件事；⌥⇧Space 开箱就能用，不需要先改任何设置。

- **默认**：⌥⇧Space，不管 ⌘Space 空不空着都不去抢。设置里的说明写「现在用 ⌥⇧Space。想用 ⌘Space 打开 Sesame，点右边接管。」
- **点了「接管 ⌘Space…」**：⌘Space 空着就立刻用上，弹完成态「好了，以后按 ⌘Space」；被聚焦或 Alfred / Raycast 占着就弹下面的接管卡（k / k2），告诉用户去哪改，Sesame 每秒读一次设置，空出来就接上（盯 10 分钟）。卡上点「先用 ⌥⇧Space」或按 Esc = 放弃这次接管，回到默认。
- **升级用户**：旧版在 ⌘Space 空着时会自己用它。已经在用 ⌘Space 的人升级后保持 ⌘Space（启动时判一次并记下来），不会被悄悄换掉；原来就在用备用键的照旧。
- 实现：`HotKeyPlan.choose(custom:commandSpace:spotlightOn:launcher:)`、`HotKeyPlan.takeoverAtLaunch = false`、`HotKeyPlan.wantsCommandSpace`（SesameCore，单测 `WO20261003Tests`）。

**每个元素为什么在**

| 元素 | 理由 |
|---|---|
| 标题「用 ⌘Space 打开 Sesame？」 | 一句话说清这一步要用户决定什么 |
| 小字（聚焦版）「在打开的设置里取消勾选「显示“聚焦”搜索」，Sesame 会自动接上。」 | 用户到了设置页只需要做这一件事；「显示“聚焦”搜索」是系统设置里那一项的原文，照着找就行；「自动接上」告诉他不用回来再点什么 |
| 小字（Alfred / Raycast 版）「⌘Space 正由 Alfred 使用。在它的设置里「General › Alfred Hotkey」换个键，Sesame 会自动接上。」 | 占着键的是另一个 App，Sesame 不碰它的配置，只告诉用户去哪改 |
| 主按钮「去设置 ↩」/「打开 Alfred 设置 ↩」 | 聚焦版用 `x-apple.systempreferences:com.apple.Keyboard-Settings.extension?Spotlight` 直接打开「键盘快捷键 › 聚焦」那一页（macOS 26.5 实测）；启动器版打开对方的设置。只是打开页面，不改任何设置 |
| 次按钮「先用 ⌥⇧Space」 | 不想动系统设置的人照样能用，按钮上直接写出备用键，不用另记 |
| 完成态「好了，以后按 ⌘Space」+「轻按打开，按住直接说。」 | 用户关掉聚焦快捷键后，Sesame 每秒只读一次设置（最多 1 秒就发现），立刻注册 ⌘Space 并弹出这一张；1.8 秒后自动进入开场页（已看过开场页的就直接收起） |

删掉的：「为什么要用 ⌘Space」的解释段、「以后再说」第三个按钮（Esc 就是以后再说）、聚焦快捷键的截图教程。

**层级**：一级是标题；二级是那一行小字；按钮三级，主按钮默认选中（回车就去设置）。

**交互三问**

1. 用户场景：在设置里点了「接管 ⌘Space…」，而 ⌘Space 正被聚焦或启动器占着；这时 Sesame 在用备用键。
2. 操作决策：「去设置」= 我要 ⌘Space（Sesame 打开对应页面并等着）；「先用 ⌥⇧Space」/ Esc = 这次不改，回到默认；什么都不点、自己去关了聚焦快捷键 = 同样会被发现并接上（盯 10 分钟）。
3. 信息层级：一级「用 ⌘Space 打开 Sesame？」；二级「去哪改哪一项」；不需要的：为什么、聚焦是什么、备用键的由来。

**聆听态（按键 v）**：复用已有的声波和实时转写（已定稿的字是正文色，未定稿的字更浅，末尾是光标）。右侧把「正在听 esc」换成「松开就发送」+ 按下状态的当前热键键帽（如 ⌘ space），告诉用户怎么结束。

**麦克风权限说明（按键 m）**：第一次按住热键时，在系统弹窗之前先出现这一张：

- 标题「按住 <当前生效的键>，直接说」：先说好处，再要权限。
- 一句话理由「Sesame 要用麦克风听你说的这一句。只在你按住时收音，松开就停。」：讲清用途和边界，这是用户最担心的事。
- 「允许麦克风」是默认按钮，按下后才触发系统的权限弹窗；「先不用」不惩罚，之后照样可以打字用。

**层级**：一级是标题那句；二级是理由；按钮是三级。

### 6. 分享我的数字（按键 4s / c；App 导出的分享卡 `png/17-share-card(-dark).png`）

产品负责人已勾选。开场页的次级按钮「分享」导出一张 1200×675 的 PNG（推特不裁切的尺寸），存到「下载」并在访达里选中，同时复制到剪贴板。

**交互三问**

1. 用户场景：第一次打开看到「2,708 个 AI 产物」，觉得这个数字值得晒；或者从菜单栏再打开开场页想截个图发出去。此时他要的是「一张拿去就能发的图」，不是自己截屏再裁。
2. 操作决策：只有一个按钮「分享」，点一下做完三件事（存「下载」、访达选中、复制到剪贴板），不弹保存对话框、不让选格式、不让选主题（跟随面板当前的浅色或深色）。按钮随后 2 秒显示「已存到下载并复制」，告诉他图在哪、可以直接粘贴。不放「发到推特」：那要登录授权，也会把用户带离当前界面。
3. 信息层级：卡片一级是那句第一人称的话「我的 2,708 个 AI 产物，动动嘴就调出来。」（数字用强调色）；二级是按类型的分组计数（为 0 的组不显示）；三级是左上角的芝麻图标和底部的「Sesame · 网站 · GitHub 地址」（网站地址先用占位）。**卡片上不出现任何标题、路径或人名**，只有数字，所以谁都能放心发。

**每个元素为什么在**

| 元素 | 理由 |
|---|---|
| 左上芝麻图标 | 看图的人第一眼知道是哪个产品；用 App 图标原图，不另画 |
| 「我的 N 个 AI 产物，动动嘴就调出来。」 | 发图的人在替自己说话，所以是第一人称；文案在 `share.headline`，`%@` 是数字 |

## 识别点：一粒芝麻 + 一次微光

只有这两样，别的地方不做品牌表达。

**标志（2026-10-02 定稿：v3-a 石墨 · 浮雕棱）。** 石墨色的 macOS 圆角方形底上，一粒象牙白芝麻，按真实芝麻的比例做（实测约 2.8 × 1.7 mm，图标里取 1.86 : 1），一头尖、一头圆。中间的纵向棱线只靠同色的一侧亮、一侧暗做出微微隆起，不加任何带颜色的线或光。菜单栏是单色模板图标：细长剪影，棱线镂空成一道细缝。定稿矢量和 AppIcon 在 `logo/final/`，比稿过程在 `png/logo-sesame-v3-board.png` 等。

**品牌色从图标底色取，不从光取。** 主色就是图标里的两种颜色：石墨和象牙白。界面里不再有色相强调色：

- 浅色模式下强调色是石墨 `#34323A`（图标底色），深色模式下是象牙白 `#EFE6D8`（种子本身）。
- 为什么不另找一个强调色：图标本身没有彩色，界面上冒出一个蓝或橙会和标志对不上；石墨和象牙白在两种模式里天然一深一浅，正好各自承担「比正文更重一点」的角色。
- 强调靠字重而不靠颜色：意图动词是 600 字重 + 强调色，目标名是 500 字重 + `--text-2`。

**唯一的品牌动效：微光扫过。** 面板出现时，输入条左侧的芝麻标志上有一道浅色微光沿棱线方向斜着扫过一次（900ms，延迟 120ms，之后不再出现）。面板本身只做 180ms 的淡入加 1% 缩放，属于系统级的普通过渡，不承担品牌表达。原来的拱门展开、小门滑开都已去掉。

除此之外，状态切换只做 260ms 的淡入加 4px 位移，面板高度跟着内容平滑变化。`prefers-reduced-motion` 下全部降为瞬时。

唯一保留的彩色是确认态里的 `--danger` 红（废纸篓图标和「移到废纸篓」按钮文字）：它是系统语义色，表示「这一步有破坏性」，不是品牌色，macOS 自己的破坏性按钮也是红色。

强调色在界面里只出现在：标志、意图行的动词、聆听声波、光标、解析时输入条下沿的流光（流光用强调色 55% 透明度）。选中行、确认态焦点环本来就是中性灰，不用强调色。

## 层级

1. **结果区**（一级）：19px 半粗标题、46px 图标格子、浅色卡片底。
2. **意图行**：12.5px，动词用品牌色，目标用正文色，类型（本机服务 / 网页 / Claude 页面 / 文件 / 系统信息）用小徽标。
3. **输入条**（最弱）：17px 常规字重、次级文字色。字号不小是因为它要能改，颜色压下去是因为结果出来以后它就不重要了。

## 状态里的取舍

- **意图预览**用和成功态同形的骨架（图标格、两行字），结果来了不会跳。
- **成功**：图标、「已打开 名称」、一行出处（地址 + 来自哪次 Claude Code 会话）。出处是给用户确认「找对了」的，不是路由信息。右侧留空，理由见上。
- **信息卡片**：大数字是剩余量，底部是已用 / 总量和重置时间。
- **候选列表**：每行右边是类型标识（图标区分、不另配颜色），只有选中行显示 ↩。网站图标用站点自己的颜色，Claude 页面用一个中性的星芒图标，不用 Anthropic 的标志。
- **确认**：只在不可逆操作出现。「取消」是默认按钮（实底 + 外圈焦点环 + ↩），放在最右；「移到废纸篓」是浅底红字。列出 3 个最大的文件，加「另外 57 个」。
- **没找到**：两行，「已经做了」写搜过哪里，「需要你」写下一步要给什么线索。
- **菜单栏下拉**：最近 5 条、索引条数与更新时间、设置、退出。

按工作单要求，面板里没有聊天历史、没有设置入口、没有底部快捷键提示栏、没有成本信息。

## 反模板自检（taste-skill / minimalist-skill）

- 没有 AI 紫、没有霓虹外发光、没有渐变大字；没有色相强调色，只用图标里的石墨和象牙白。
- 没有 emoji。图标全部来自 Phosphor Icons v2.1.1（MIT），以 `<symbol>` 内联进文件，没有手画的图标路径。
- 界面文案和本文里没有 em-dash 与 en-dash（生成原型时脚本逐字检查，出现即失败）。
- 文案用真实语境的数据：2,708 条记录、150 GB、9.2 GB。
- 浅色和深色两套 token 都定义了，每个状态都截了两套。
- 不用纯黑或纯白做文字和底色。
